# Quy tắc cho ứng dụng FE

Đọc `docs/ARCHITECTURE.md`, `docs/SPEC_REVIEW.md` và `docs/IMPLEMENTATION_STATUS.md` trước khi tiếp tục. Đặc tả nghiệp vụ gốc ở `fe-specs/`; route và nghiệp vụ lấy từ catalog 0.3.0; response theo schema hiện hành trong code và tiêu chí tối giản của người dùng.

Theo yêu cầu người dùng ngày 24/10/2026, tổ chức code tham khảo `D:/TTZinza/vietcd/frontend`: `app`, `components`, `features`, `hooks`, `lib`, `services`, `stores`, `types`, `mocks`. Thay thế các đường dẫn cấu trúc đích `shared/...` cũ trong tài liệu bằng cấu trúc ở `docs/ARCHITECTURE.md`; giữ nguyên các yêu cầu nghiệp vụ, quyền, validation, trạng thái và cache.

- Schema/DTO nghiệp vụ nằm tại `features/<feature>/schemas` và `types`; không tạo lại file DTO chung chứa mọi feature.
- Route chỉ ghép màn. `components/ui` và `components/forms` không fetch dữ liệu. Feature component dùng hooks; hooks gọi service; service gửi HTTP qua `services/api-client.ts`.
- MSW chỉ chặn HTTP ở môi trường development/test. Chỉ `app/providers.tsx` được dynamic import browser worker; component/service/store không đọc mock hoặc gọi mock DB.
- Theo yêu cầu người dùng, `mocks` gồm `data.json` lưu toàn bộ seed/policy/nội dung tệp mẫu, `db.ts` tạo và xử lý DB tạm, `handlers/*.handlers.ts` chặn từng API. `handlers/http.ts` dùng chung parse/envelope/scenario/idempotency; `browser.ts`/`node.ts` khởi động MSW. Không tạo lại folder db/data/utils hoặc file reset chuyển tiếp; node.ts reset DB và receipt cho test. Không import browser worker vào RSC.
- Handler chỉ đăng ký endpoint, chuyển request đã parse cho DB và định dạng HTTP response/header. Không đặt fixture, lọc/mutate collection hoặc kiểm tra nghiệp vụ trong handler. DB nhận DTO/viewer/version đã parse, không nhận Request/Response/MSW. Seed và policy nằm trong `mocks/data.json`.
- Không tạo lại `src/contracts/registry.ts`, `manifest.json` hoặc barrel schema riêng cho mock. Contract theo feature chỉ khai báo interface TypeScript; service/handler tái sử dụng schema. Test kiểm tra HTTP routes trực tiếp với API catalog. Lỗi quyền hiển thị tại màn, 404 dùng `app/not-found.tsx`; không thêm route `/403`, `/404` riêng.
- Import trực tiếp file cần dùng; không thêm barrel `index.ts`, `hooks.ts`, `client.ts` ở gốc feature. Cross-feature chỉ import đúng schema/type/hook/component cần thiết, tránh kéo UI vào service hoặc tạo vòng phụ thuộc. Services và types dùng chung không import feature.
- DTO/payload/query/result nằm trong `types`, validation runtime nằm trong `schemas`. Chia schema theo thực thể/nhóm nghiệp vụ; mỗi màn có file component riêng. Tái sử dụng DTO/schema khi các màn cần cùng dữ liệu; dùng Row cho danh sách khi detail có dữ liệu không cần gửi. Không tạo nhiều bản giống nhau theo tên endpoint.
- Model nội bộ, state/clock, hàm dựng DTO và nghiệp vụ mock nằm trong `mocks/db.ts`, nhóm theo chức năng; handler gọi trực tiếp các nhóm API được export từ file này. Không lưu label, tổng giờ hiện tại, cờ quá hạn, freshness hoặc quyền phản hồi theo người xem trong model gốc. Snapshot báo cáo/lần nộp cần lưu vì là dữ liệu đã chốt. Response chỉ trả trường cần để hiển thị hoặc thay đổi dữ liệu, gồm ID/version/quyền cần cho thao tác. Rà toàn bộ nơi dùng trước khi xóa; list dùng Row rút gọn, detail giữ trường cho xem/sửa. Model chỉ giữ dữ liệu có nơi dùng trong màn hoặc nghiệp vụ hỗ trợ màn; tên ngắn nhưng rõ, không giữ trường dự phòng. Trường nội bộ không tự động đi vào response; không thêm field chưa có nguồn. FormOption là kiểu hiển thị, không phải DTO API.
- Màn cha tải dữ liệu và ghép giao diện; form, thao tác quản trị và các phần hiển thị phân tích có trách nhiệm riêng nằm trong file riêng khi đủ lớn. PermissionGate ở layout; UI/forms dùng chung không chứa policy phiên/quyền hoặc gọi feature API/hook. Không thêm tầng hoặc file chỉ để chuyển tiếp lời gọi.
- Theo tiêu chí người dùng: code đủ chức năng, gọn, dễ đọc; mỗi tầng chỉ xử lý đúng trách nhiệm. Form kiểm tra input một lần và trả kiểu suy ra từ schema. Hook chuẩn hóa query một lần rồi dùng cùng dữ liệu cho key và request; analytics dùng scope đã kiểm tra từ URL. Keys không parse. Service nhận input có kiểu, gửi HTTP và giao kiểm tra response cho API client; không parse lại input. HTTP handler là biên server độc lập nên vẫn kiểm tra request; DB không parse lại DTO đã nhận từ handler. Khi tạo payload mới từ nhiều nguồn hoặc chỉ lấy các trường thay đổi, có thể kiểm tra lại hình dạng mới đó.
- Tên ngắn nhưng rõ: `AlertDto`, `TaskQuery`, `CreateTaskInput`, `UpdateTaskArgs`, `alertSchema`. Không lặp tên feature trong tên thực thể, không giữ alias chỉ đổi tên biến hoặc wrapper chỉ gọi tiếp một hàm. Không thêm abstraction chỉ để giảm số dòng.
- Theo yêu cầu refactor toàn bộ, bỏ generator và endpoint metadata. `api/*.contract.ts` chỉ khai báo interface API; service gọi HTTP trực tiếp; hook dùng React Query trực tiếp. Schema/types được bảo trì như code thông thường, tái sử dụng validation, không sinh lại từ đặc tả.
- `services` chỉ gồm `api-client.ts` và `http-error.ts`. Kiểu options, token trong bộ nhớ và cơ chế refresh dùng chung nằm cùng HTTP client; không tách thêm file nhỏ chỉ để chuyển tiếp. Login/refresh service tiêu thụ token rồi trả SessionDto; không lưu credential trong Query cache, Zustand hoặc localStorage.
- Service dùng trực tiếp Axios `get/post/patch/put`, truyền query qua `params`, rồi kiểm tra response bằng `parseResponse(schema)` dùng chung. Axios xử lý serialize, timeout và cancellation; interceptor thêm header, refresh và chuẩn hóa lỗi. Không viết lại wrapper cho từng HTTP method.
- API theo resource/subresource của catalog 0.3.0. Entity dùng `id`; path/quan hệ dùng `<resource>Id`, chuỗi opaque trim dài 1–100; không đổi ID thành number, slug hoặc project code. Hook chuẩn hóa path ID bằng `queryIdSchema` một lần vào biến local rồi dùng cùng giá trị cho key/quyền/service, không sửa tham số hook. Schema danh sách dùng `listQuerySchema.shape`, response dùng `Page<T>`/`paginationSchema`; query/filter truyền một object qua Axios params. Service nhận path ID trước, query/payload tiếp theo, options cuối; không lặp path ID trong body nếu contract không khai báo. Không thêm slug hoặc đổi route chỉ để đồng dạng tên; đối chiếu catalog và cập nhật đồng bộ khi contract thay đổi.
- Không lặp `enabled: Boolean(id)` ở màn khi hook đã kiểm tra ID, hoặc kiểm tra session rỗng trước `hasPermission` vốn đã xử lý trường hợp này. Dialog đã nhận entity thì dùng callback reload từ cha; không đăng ký thêm query chỉ để lấy refetch. Truyền entity hoặc các trường cần dùng, tránh truyền cả hai. Hàm dựng DTO trả kiểu đã khai báo; handler kiểm tra response một lần, client kiểm tra dữ liệu nhận qua HTTP ở biên riêng. Mutation đã invalidate query thì component không gọi refetch lại cùng dữ liệu. Dữ liệu tạm cần tồn tại qua render phải khởi tạo một lần.
- Không khai báo một endpoint đã hoàn thành chỉ vì đã có schema/service. Cập nhật trạng thái handler, UI và test riêng trong tài liệu trạng thái.
- Chạy `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` cho các thay đổi phù hợp. Tests tích hợp phải gọi feature service qua HTTP/MSW, không thay API client bằng mock function.
