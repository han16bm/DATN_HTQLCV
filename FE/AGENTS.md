Đọc `docs/ARCHITECTURE.md`, `docs/SPEC_REVIEW.md` và `docs/IMPLEMENTATION_STATUS.md` trước khi tiếp tục. Đặc tả nghiệp vụ gốc ở `fe-specs/`; route và nghiệp vụ lấy từ catalog 0.3.0; response theo schema hiện hành trong code và tiêu chí tối giản của người dùng.

Theo yêu cầu người dùng ngày 24/10/2026, tổ chức code tham khảo `D:/TTZinza/vietcd/frontend`: `app`, `components`, `features`, `hooks`, `lib`, `services`, `stores`, `types`, `mocks`. Thay thế các đường dẫn cấu trúc đích `shared/...` cũ trong tài liệu bằng cấu trúc ở `docs/ARCHITECTURE.md`; giữ nguyên các yêu cầu nghiệp vụ, quyền, validation, trạng thái và cache.

- Schema/DTO nghiệp vụ nằm tại `features/<feature>/schemas` và `types`; không tạo lại file DTO chung chứa mọi feature.

- MSW chỉ chặn HTTP ở môi trường development/test. Chỉ `app/providers.tsx` được dynamic import browser worker; component/service/store không đọc mock hoặc gọi mock DB.
- Theo yêu cầu người dùng, `mocks` gồm `data.json` lưu toàn bộ seed/policy/nội dung tệp mẫu, `db.ts` tạo và xử lý DB tạm, `handlers/*.handlers.ts` chặn từng API. `handlers/http.ts` dùng chung parse/envelope/scenario/idempotency; `browser.ts`/`node.ts` khởi động MSW. Không tạo lại folder db/data/utils hoặc file reset chuyển tiếp; node.ts reset DB và receipt cho test. Không import browser worker vào RSC.
- Handler chỉ đăng ký endpoint, chuyển request đã parse cho DB và định dạng HTTP response/header. Không đặt fixture, lọc/mutate collection hoặc kiểm tra nghiệp vụ trong handler. DB nhận DTO/viewer/version đã parse, không nhận Request/Response/MSW. Seed và policy nằm trong `mocks/data.json`.
- Không tạo lại `src/contracts/registry.ts`, `manifest.json` hoặc barrel schema riêng cho mock. Contract theo feature chỉ khai báo interface TypeScript; service/handler tái sử dụng schema. Test kiểm tra HTTP routes trực tiếp với API catalog. Lỗi quyền hiển thị tại màn, 404 dùng `app/not-found.tsx`; không thêm route `/403`, `/404` riêng.
- Import trực tiếp file cần dùng; không thêm barrel `index.ts`, `hooks.ts`, `client.ts` ở gốc feature. Cross-feature chỉ import đúng schema/type/hook/component cần thiết, tránh kéo UI vào service hoặc tạo vòng phụ thuộc. Services và types dùng chung không import feature.
- DTO/payload/query/result nằm trong `types`, validation runtime nằm trong `schemas`. Chia schema theo thực thể/nhóm nghiệp vụ; mỗi màn có file component riêng. Tái sử dụng DTO/schema khi các màn cần cùng dữ liệu; dùng Row cho danh sách khi detail có dữ liệu không cần gửi. Không tạo nhiều bản giống nhau theo tên endpoint.

- Theo tiêu chí người dùng: code đủ chức năng, gọn, dễ đọc; mỗi tầng chỉ xử lý đúng trách nhiệm. Form kiểm tra input một lần và trả kiểu suy ra từ schema. - Theo yêu cầu refactor toàn bộ, bỏ generator và endpoint metadata. `api/*.contract.ts` chỉ khai báo interface API; service gọi HTTP trực tiếp; hook dùng React Query trực tiếp. Schema/types được bảo trì như code thông thường, tái sử dụng validation, không sinh lại từ đặc tả.
- `services` chỉ gồm `api-client.ts` và `http-error.ts`. Kiểu options, token trong bộ nhớ và cơ chế refresh dùng chung nằm cùng HTTP client; không tách thêm file nhỏ chỉ để chuyển tiếp. - Service dùng trực tiếp Axios `get/post/patch/put`, truyền query qua `params`, rồi kiểm tra response bằng `parseResponse(schema)` dùng chung. Axios xử lý serialize, timeout và cancellation; interceptor thêm header, refresh và chuẩn hóa lỗi. Không viết lại wrapper cho từng HTTP method.
